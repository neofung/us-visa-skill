## 功能需求详细说明

> **界面说明：** 本技能为对话式 Claude Code Skill，仅 FR-001/FR-002 涉及用户交互界面要素（模式菜单、路径输入）；FR-003~016 为对话式逻辑功能，无独立界面，"界面/交互要求"不适用。

> **子 Agent 承担映射（2026-08-04）：** FR-001/002 → 主 agent（编排层）；FR-003/004 → DS-160 处理 agent；FR-005~010 → 审核 agent；FR-011~016 → 面签模拟 agent；FR-017 → 三子 agent 整体承载；FR-018/020 → 主 agent；FR-019 → DS-160 处理 agent（生成）＋审核/模拟 agent（读取）。

### FR-001：技能触发与模式选择

| 属性 | 内容 |
|------|------|
| 来源需求 | REQ-016 |
| 关联流程 | BPF-001 |
| 优先级 | P0 |
| 涉及角色 | 用户、技能 |

**功能描述：**
技能可通过 `/技能名` 或自然语言触发。触发后加载并显示操作模式菜单（①DS-160审核 ②面签模拟 ③全流程），引导用户选择。

**用户故事：**
> 作为用户，我希望输入 `/美签` 或"帮我审核 DS-160"就能启动技能，以便快速进入审核或模拟流程。

**输入：**

| 字段名 | 类型 | 必填 | 校验规则 | 说明 |

| 模式选择 | enum | 是 | ∈{审核, 模拟, 全流程} | 操作模式 |

**输出/响应：**

| 场景 | 输出内容 | 说明 |
|------|---------|------|
| 成功 | 显示模式菜单并引导下一步 | — |
| 未识别 | 提示重新表达触发意图 | — |

**业务规则：**
1. 支持两种触发方式，触发成功率 100%（REQ-016、SC-016-1）。
2. 全流程模式为"先审核后模拟"的顺序（BPF-001）。
3. 加载后按流程引导用户指定输入位置与操作模式（SC-016-2）。

**界面/交互要求：**

| 场景 | 输出内容 | 说明 |

**业务规则：**
1. 输入位置必须用户指定，技能不得越界扫描，100% 仅读取指定位置（REQ-001、SC-001-1）。

### FR-003：PDF 解析与字段提取

| 属性 | 内容 |
|------|------|
| 来源需求 | REQ-002 |
| 关联流程 | BPF-002 |
| 优先级 | P0 |
| 涉及角色 | 技能 |
| 依赖 | FR-002（输入位置读取） |

**功能描述：**
解析含完整表单内容的 DS-160 PDF，提取结构化字段（个人信息、护照、行程、工作、家庭、安全类问题等），支持多份解析且数据相互独立。文字版 PDF 经 Claude 原生 Read 提取；图片/扫描型 PDF 经依赖技能 tencentcloud-ocr（腾讯云 OCR，凭据由用户手动输入）识别后提取。

**用户故事：**
> 作为用户，我希望技能自动从每份 PDF 提取全部关键字段，以便后续逐字段审核；遇到图片型页面也能自动识别。

**输入：**

| 字段名 | 类型 | 必填 | 校验规则 | 说明 |
|--------|------|------|---------|------|
| PDF 文件 | file | 是 | 文字可提取或图片/扫描型 | 完整表单内容 |
| OCR 凭据（SecretId/SecretKey） | string | 仅图片型 | 用户手动输入 | 每次会话提供，不存储（TC-OTH-003） |

**输出/响应：**

| 场景 | 输出内容 | 说明 |
|------|---------|------|
| 成功（文字版） | 每份 PDF 的结构化字段数据 | 独立存储 |
| 成功（图片型） | 经腾讯云 OCR 识别的结构化字段数据 | 需用户提供凭据 |
| OCR 失败 | 明确提示该份识别失败并跳过 | 不中断其他文件 |

**业务规则：**
1. 关键字段提取完整率 ≥ 95%（SC-002-1）。
2. 多份数据隔离，不混淆成员（SC-002-2）。
3. 图片/扫描型 PDF 走依赖技能 tencentcloud-ocr（腾讯云 OCR）识别（TC-INT-003）。
4. OCR 凭据由用户每次手动输入，技能不存储、不写盘（TC-OTH-003、NFR-SEC-004）。
