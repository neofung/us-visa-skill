## 澄清结论

### 项目背景与目标
用户（Neo）本人及其家庭正在准备申请美国 **B1/B2（旅游/商务）签证**，计划**以家庭为单位**（含孩子）一起申请、一起面签。需要一个 Claude Code 技能提供两项核心能力：
1. **DS-160 读取审核**：读取每位家庭成员已填写的 DS-160 完整表单 PDF，从签证官视角进行**全面审核**（表单内部前后矛盾、与真实情况一致性、拒签高风险因素、常见填写错误），并对多份 PDF 做**跨成员一致性比对**，输出中文审核报告。
2. **面签模拟**：模拟**家庭一起面签**的问答场景，**中文出题 + 英文模拟 + 中文点评**，提问**基于真实资料个性化 + 通用题库**结合，对**每个回答**给出点评与优化建议。

### 目标用户与角色
- **主申请人（用户本人）**：面签时主要回答问题者；技能的主要使用者。
- **家庭成员（配偶、孩子）**：一起面签；孩子可能被问简单问题（如姓名、学校）。
- **AI 技能**：承担"审核助手 + 面签陪练"双重角色；由主 agent 编排三个子 agent（DS-160 处理 / 审核 / 面签模拟）实现。

### 核心范围
1. **DS-160 审核模块**
   - 读取用户指定文件/目录中的多份 DS-160 完整表单 PDF
   - 逐字段审核：前后矛盾、高风险因素、常见填写错误
   - 跨家庭成员一致性比对
   - 输出中文审核报告到用户指定位置
2. **面签模拟模块**
   - 家庭一起面签场景模拟
   - 中文出题 + 英文模拟 + 中文点评
   - 基于真实资料的个性化提问 + 通用题库
   - 逐答点评与优化建议
3. **子 Agent 架构模块（2026-08-04 新增）**
   - 三子 agent：DS-160 处理 / 审核 / 面签模拟，以独立 subagent 定义（agents 目录）
   - 主 agent 按"处理 → 审核 → 模拟"流水线编排，可中途切入
   - DS-160 处理 agent 生成结构化中间文件（JSON）衔接后续环节
   - 中间文件临时落盘于用户指定位置，会话结束由主 agent 清理

### 明确排除的范围
- 签证缴费
- 面签预约
- 材料清单辅助
- 签证状态查询
- 其他国家签证相关功能

### 关键假设
1. 输入的 PDF 为**含完整表单内容**的版本（已确认，非仅确认页摘要）。
2. 技能以 **Claude Code Skill** 形式运行，用户通过 `/技能名` 或自然语言触发。
3. **输入输出位置均由用户指定**，技能不擅自决定存放位置。
4. 敏感个人信息**不脱敏**（本仓库为私有且纳入 git 版本管理）。
5. 审核报告与面签模拟输出语言：报告为中文；面签模拟中对话为英文，出题与点评为中文。
6. Skill 源码存放于 `skills/`，软连接安装到 `.claude/skills/`；需求分析文档存放于 `PRD/`。
7. 三子 agent（DS-160 处理 / 审核 / 面签模拟）以独立 subagent（agents 目录）形式定义，由主 agent 按流水线编排，可中途切入。
8. DS-160 处理 agent 生成的中间文件为临时产物：存放于用户指定位置，会话结束由主 agent 清理，不纳入版本库。

### 遗留风险/开放问题
1. **PDF 可解析性**：~~若某些 PDF 为扫描件（图片）而非可提取文字，需要 OCR 能力。此问题在 P5 技术约束阶段处理。~~ **已关闭（2026-08-03；OCR 方案 2026-08-04 最终定为依赖技能 tencentcloud-ocr）**：用户确认材料为在线表单逐页打印/另存的文字版完整表单 PDF（A 类），主流程经 Claude 原生 Read 工具直接文本提取，无需 OCR；图片/扫描型兜底方案为依赖技能 **tencentcloud-ocr**（腾讯云通用文字识别·高精度版），凭据 SecretId/SecretKey 由用户每次手动输入、不落盘（见 TC-INT-003、TC-OTH-003、NFR-SEC-001/004）。
2. **DS-160 字段覆盖完整性**：需与官方 DS-160 字段清单对齐，确保审核覆盖所有关键字段。实现阶段需核对官方字段表。
3. **面签问题的真实性**：面签题库需贴近真实 B1/B2 面签常见问题，需参考权威面签经验资料。
